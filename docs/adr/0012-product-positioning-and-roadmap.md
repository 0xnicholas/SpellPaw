# Product positioning: lifecycle intelligence for AI-native builders

Phase 1–2 product decisions, re-examined and locked after M2 shipped. SpellPaw's core value is **customer lifecycle intelligence** — turning the user's Audience into a trackable, analyzable, follow-up-able asset. Content publishing and Inbox conversations are the data entry points (Content Touch / Conversation); the Customer Graph and AI insights (Persona/State) are the product.

**Why**: The original concept ("an external-communication AI operating system for SMB and AI-native builders") left the value proposition unverifiable and the target user ambiguous. As built through M2, the product was indistinguishable from a multi-channel scheduling tool (a red ocean against Buffer/Hootsuite). The re-examination (grilling session, 2026-08-03) resolved six decisions: core value = lifecycle intelligence; primary persona = AI-native builders (micro-SMB secondary); first real channel = Twitter/X, inserted between M3 and M4 so M4 ships a real-data closed loop (real publish → real short-link clicks → Content Touch → Graph); M5 = release readiness (docs, E2E, deployment, perf/security, landing, English launch) instead of more features; Phase 1 limits are abuse guardrails (3 Channels / 50 Posts / 1000 Contacts, env-configurable) not a paywall, with pricing deferred until real usage data exists; product language = English primary, zh second.

**Considered alternative**: Serving SMB marketing teams first for cash flow. Rejected because the repo's technical decisions were already irreversibly builder-leaning (BYOK — ADR-0005, embedded MCP — ADR-0010, self-hosted short links — ADR-0009), and a solo builder cannot run a sales-led SMB motion; product-led growth (docs, community, English launch) is the viable path. Keeping both personas as equals was also rejected — the intersection of their needs is the undifferentiated publishing tool.

**Consequence**: M3–M5 scope is now fixed: M3 MCP + AI provider unchanged; X real integration lands before M4 (X API cost + developer review are a schedule risk to track); M4 delivers Graph with real data, analytics, i18n en/zh; M5 is release readiness with English-first narrative; M6+ is feedback-driven (Inbox Phase 1, analytics depth, orchestration are all candidates, in that order). Free-plan limits must be env-configurable guardrails, and the pricing model (BYOK + usage vs subscription) stays undecided until real usage distribution exists. Content Touch data quality now depends on the X integration — the mock adapters no longer represent the revenue-critical path.
